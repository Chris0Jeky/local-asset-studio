# P35: character consistency qualification design

Status: implemented design; every new image outcome is planned. Base: `0270760a3d4fd9e005a1788bba59d8242b77c2f4`.

## Kill criteria first

1. Any candidate automatic acceptance metric that contradicts an available, bytes-bound owner Keep or Not this mark is disabled for gating. Missing or unverifiable owner calibration also disables gating. Synthetic test labels cannot establish owner agreement.
2. No route is qualified from successful submission, a structural graph check, a few selected examples, or an aggregate score that hides a failed pose family. Missing, unsupported, failed and uncertain cells remain in the planned denominator.
3. Unknown dispatch stops the run. No automatic retry, fresh request identity, model switch, package change, installation or direct ComfyUI submission is permitted.
4. Reference count/role, subject, facet, graph, source bytes, backend or resource mismatch blocks the affected run. Semantic instructions do not become hard geometric control or protected-pixel guarantees.
5. A generation receipt, visual review, Keep mark, project acceptance and licence decision remain separate fields. No new generation or visual review is available in this hosted task.

## Intent and approach

Qualify the Studio's existing multi-reference portfolio against Priority 1 rather than add a second catalog, queue or model warehouse. This run adds a prototype package only; it does not change the production app or catalog. The owner can bind existing Studio uploads, inspect a frozen plan, and deliberately start it through existing Production APIs.

Three approaches were considered. A new all-purpose generator would duplicate Studio ownership and demand unmeasured runtime changes. A documentation-only benchmark would leave calibration, incomplete denominators and uncertain submissions unenforced. The selected approach is a deterministic qualification layer plus a bounded adapter to current Studio services. This is an implementation decision under the owner's instruction to take the lead.

## Components and interfaces

`qualification.py` owns six human axes (identity, outfit/detail, pose/geometry, style, anatomy/contact, composition), ten pose families, explicit conflict findings, conservative metric calibration and failure-inclusive summaries. Diagnostic landmark/overlap/protected-region measurements never fill human score fields.

`suite.json` declares twenty source situations (two per family), three declared original-character placeholders, three fixed seeds and four current route contracts. Real canon, donor, style and corrected-guide bytes remain owner supplied. Every full-suite route/case/seed cell is retained even when unsupported. A small screening profile precedes the full matrix and cannot establish qualification.

`routes.json` and `graphs/` retain exact pinned native API graphs, control and role mappings, preprocessing, sources, model/adapter terms and explicitly estimated budgets. Current portfolio: Klein 4B reference baseline; Klein 9B Copy Pose; Klein 9B corrected skeleton; conditional Qwen Image Edit 2511 three-reference Lightning. Frontier Qwen-Image 2.1 multi-reference and FLUX.3 remain separate research candidates pending new native contracts.

`plan.py` validates graphs and bindings, freezes source/config identities, rejects missing references and unsupported roles, compiles existing Studio Production requests and writes planned review sheets. It never connects to a server. Paired seeds compare routes; donor-attribute and role-order counterfactuals expose leakage rather than trusting similarity alone.

`owner_run.py` is a narrow loopback client with explicit prepare/start/status operations and a durable journal. The owner supplies the exact Studio workspace identity. It checks the active backend, prepared input bytes and source graph identity. Preparation never generates. Explicit start is the only generation action; missing responses or malformed receipts stop further mutations. A repeated launcher observes retained work instead of resubmitting it.

`run.py` is the single evidence command: unit tests, structural route/suite checks, deterministic plan/calibration evidence and hash verification. Regenerable artifacts go under `.runtime/`. Committed evidence is small text; there are no generated pictures or private references in this contribution.

## Qualification decisions

Human scores use anchored 0–4 scales and separate unreviewed/uncertain values. Identity is per subject; anatomy/contact includes support, grip, occlusion and viewpoint rather than body keypoints alone. The decision surface reports the worst required axis, each pose family, Keep rate, failures, retries, active intervention time and runtime/VRAM/RAM; no weighted mean can conceal a hard failure.

Metrics need an immutable, owner-attested snapshot because the current Workspace mark mutation does not record actor provenance. Calibration freezes threshold and model/preprocessing identity before held-out groups. Same-source crops and generated derivatives share a split group. Any observed disagreement disables the gate; agreement is scoped and is never permission to accept an asset.

Automatic evidence is limited to properties it measures: visible-landmark geometry, silhouette overlap, declared palette differences and exact pixels in a registered same-canvas protected region. Learned embedding/VLM scores are optional diagnostics until actual owner labels establish validity for the named route/family; face recognition assumptions do not transfer automatically to anime.

## Review focus

- Missing or contradictory owner labels; fixtures masquerading as real calibration.
- Partial trials, unsupported multi-character cells, selective receipt imports and duplicate hashes inflating acceptance.
- Corrected guide accidentally fed through a detector; wrong reference order; strong style overriding outfit colours.
- Lost create/start responses, process death after durable intent, concurrent double-click and backend drift.
- Model-card memory claims transferred to a different precision, Comfy build, AMD backend or host-memory regime.
