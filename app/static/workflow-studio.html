Headless & agents · CLI / SDK / MCP

NO BROWSER CLICKS REQUIRED

Work on the same saved workflow.

The CLI, Python SDK and optional stdio MCP adapter use the ordinary Studio service. They share Workspace revisions and the existing worker; do not start a second Studio beside the configured one.

Discover and inspect

python -m studio_workflow capabilities
python -m studio_workflow documents list
python -m studio_workflow documents get DOCUMENT_ID
python -m studio_workflow documents history DOCUMENT_ID
python scripts/workflow-mcp.py --describe

Run from the repository root. Replace uppercase placeholders with actual returned values. The last command is offline MCP schema discovery; it does not prove the host or optional dependency is installed. MCP starts in read mode; author and execute modes are separate choices.

Prepare a saved revision

Save to Workspace first. Supported non-reference image recipes can be prepared from an exact server revision; arbitrary rewiring and native widgets remain unsupported. Retain the request ID and exact arguments before sending.

python -m studio_workflow runs prepare DOCUMENT_ID --expected-revision REVISION --preset PRESET_ID --request-id PREPARATION_REQUEST_ID
python -m studio_workflow runs review PREPARATION_REQUEST_ID

Review, authorize, then observe

Preparation does not start a job. Inspect the returned recipe, source revision, record hash and ticket hash. Only authorize the exact reviewed content. After a lost response, recover the original request; a new request means a new deliberate attempt.

python -m studio_workflow runs run PREPARATION_REQUEST_ID --record-sha256 RECORD_SHA256 --ticket-sha256 TICKET_SHA256 --approve
python -m studio_workflow runs observe PREPARATION_REQUEST_ID
python -m studio_workflow runs get PREPARATION_REQUEST_ID

Document edits, static checks and hashes are not execution permission or artwork acceptance. See docs/workflow-studio/AGENT-QUICKSTART.md for editing, conflict handling and recovery, and MCP-AGENTS.md for host setup.
