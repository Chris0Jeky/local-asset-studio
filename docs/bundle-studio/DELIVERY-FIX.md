# Showcase HTTP delivery correction

13 September 2026, review follow-up to #146.

The initial fixture mocked `/static/bundle-showcase.json`, but the actual
Handler permits only HTML, JavaScript and CSS. Thus the initial browser fixture
proved interactions but missed a real 404. The review finding was correct.

The canonical JSON index is unchanged. `scripts/build-bundle-showcase.py` emits
its checked-in ES-module representation, `bundle-showcase.js`. The explorer
loads that fixed same-origin module explicitly on opening. Normal startup has
no build step, and the static extension allow-list is not broadened. This is
repository-authored data serialized by JSON, never downloaded model-card code.
The unittest gate rejects drift between canonical and generated bytes.

A separate dialog-open epoch now lets a late index finish after a recipe was
selected without dropping the selection or overwriting detached edits. Reopening
clears old apply consent and detail state. Missing-module loading remains a
visible, nonfatal no-preview condition.

Executed locally: four serialization/generation tests, JS syntax and native Node
ES-module loading (two records). Four real-Handler HTTP regressions require the
full source checkout and are skipped in this focused local file set; their
result must come from hosted CI. They assert exact served bytes and JavaScript
MIME, original JSON denial, Host refusal and path boundaries with an inert
Studio object that fails on any runtime access. No model inference is involved.

This corrects the delivery assumption in the original README/architecture:
the browser imports the generated JS representation, not the canonical JSON.
See https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import
for the native dynamic import contract (checked 13 September 2026).
