## Reconciliation rules

- Merged/closed state comes from the live GitHub API. A reference from a PR to an
  issue is evidence of related work, not evidence that the issue's complete
  acceptance is finished.
- An issue is treated as resolved only where its concrete defect is implemented,
  the PR body or issue history identifies that scope, and GitHub already reports
  the issue closed. Umbrella, research, quality, licensing and live-runtime
  issues remain open when their own acceptance still has work.
- Tests, schema checks, successful inference, creative acceptance and licensing
  are separate states. A merged PR never turns one of those states into another.
- Historical checkpoint documents retain their original dates and evidence. The
  current status for all GitHub objects is maintained here and in the opening
  section of [`CURRENT_STATE.md`](../../CURRENT_STATE.md).
