## Presentation and policy files

| File | Responsibility | Scope |
| --- | --- | --- |
| `app/static/workshop-immersive-core.css` | Production rendition container | Embeds two reviewed base64 SVG renditions because the application static handler does not serve SVG files directly; the embedded renditions are tested directly rather than assumed to be byte-for-byte copies of the source SVGs |
| `app/static/workshop-ambience-policy.js` | Pure availability and eligibility projection | Accepts only allow-listed local state; no URL, path, image bytes, credential or provider configuration |
| `app/static/workshop-ambience.js` | Stylesheet-backed availability adapter | Treats unresolved poster CSS as unknown, stylesheet failure as missing and successful load as available; no downloader or provider access |
| `app/static/workshop-ambience.css` | Effective fallback presentation | Removes only decorative poster art for token and suspended modes; leaves gradients, structure, text and controls intact |

The ambience art is decorative and has empty semantics. It carries no label, instruction, progress, readiness claim or button. It does not cover prompt fields, controls or errors. Ambience None hides the hero content and collapses its track; ordinary grid row spacing between the remaining surfaces still applies.

The selected ambience is not treated as proof that a file, provider or backend is available. The policy uses a bounded `available | missing | unknown` local asset observation. Production derives that observation from the existing immersive stylesheet rather than pre-declaring success: unresolved styles remain unknown, an error event marks the poster missing and a load event marks it available. A missing or unconfirmed poster falls back to theme tokens and a quiet HTML status; it never triggers a download or disables the workbench. Internet and backend observations do not gate an available local poster.

The test suite decodes the exact two base64 SVG renditions embedded in `workshop-immersive-core.css` and checks those shipped bytes for scripts, `foreignObject`, external `href` references and non-namespace network URLs. The source SVGs remain useful review masters, but source-file inspection is not presented as proof about different embedded bytes.

Production does not insert prototype artwork into the real result gallery. The real gallery continues to show the user's outputs and provenance. Existing examples retain their existing provenance and terms. This document does not relicense model outputs, certify character rights, treat a passing frontend test as artistic acceptance or claim that the visual environment was produced by an installed Studio model.

`app/static/workshop-immersive.css` remains the stable visual-system entrypoint and imports the core before applying narrow responsive overrides. `workshop-ambience.css` is a separate effective-state layer, so reverting the eligibility slice does not change the poster sources or user preference format.

Use normal platform fonts. Future skins/environments must remain allow-listed presentation data, not generation defaults or backend state. Motion, local loops, parallax, audio and remote media remain outside this delivery and require separate provenance, resource and execution qualification. Run the full presentation-state, fallback and viewport contracts for each addition.
