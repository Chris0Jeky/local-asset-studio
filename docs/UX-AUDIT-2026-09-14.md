# UX audit — owner feedback of 14 September 2026

The first first-hand usability statement from the owner (it answers HUMAN_TODO q-6). Everything before it
was an agent's judgement from screenshots. This page records the feedback faithfully, the root causes an
agent could confirm in code or in run receipts the same day, and the action map. Tracking issue: #278.
Companion: [UX-USE-CASE-MATRIX.md](UX-USE-CASE-MATRIX.md) (agent-driven use-case runs, once merged) and
[UX-WORKFLOWS.md](UX-WORKFLOWS.md) (the 12 September information architecture this audit measures against).

Three states stay separate throughout: a fix merged, a fix verified in a browser, and the owner saying it
now feels right. Only the last one closes this audit.

## The owner's verdict

Recorded in the owner's own framing, lightly condensed:

- **Overall.** "So much work and I feel like this whole thing is still pretty much unusable." Learning ComfyUI
  directly, or learning to draw, looks like a better investment than the Studio as it stands.
- **The generation that triggered it.** A screenshot of an existing character was attached as the reference
  to *Qwen Atelier - 1 Reference* with the brief "Use the character identity and costume from Picture 1.
  Create a fantasy portrait. Preserve the approved character design." It took over ten minutes and came back in
  a completely different art style, and not a good one.
- **Create** is "not very helpful and snappy".
- **Guided workflows** "don't seem to work": *Edit or preserve a character* is mainly advisory, does not do that
  job well either, is very wordy and "too clear" (over-explained).
- **Plan a comparison** is "all over the place"; it is not clear what it is for or how to use it.
- **Asset library** is not snappy; the review part has too little automation, no hand-holding, no
  auto-organisation, and the review options do not cover every situation. "Maybe I need an organisation engine."
- **Runs & review** is not clear: what is happening, what it is for, how it works, why one should use it, which
  situations lead here and how to get here directly.
- **Prompt Lab** is a let-down: clunky, not intuitive, not autocomplete-friendly, unclear what to do and how.
  Buttons like *Compile preview*, *Export brief*, *Export compilation* are unexplained; locked buttons never say
  what is missing; *Trace and complete source intent* is uninterpretable; and after filling everything in,
  *Review text in Create* never unlocked and the owner "was not even close to being able to create anything".
  Expectation: a place that helps build the prompt and everything around it with little effort, pulls in
  references easily, hands off to Create so the wanted image is a couple of clicks away, and picks the right
  models, LoRAs and options for the intent.
- **Scene editor** is "a bit useless too but fine", not needed now.
- **Workflow builder** (Nodes view): view movement is clunky, the UI is inconsistent with defects, the prompt
  text field is very small and hard to read whole. The guided workflow around it needs to feel supportive instead
  of a slow tour of settings, buttons and wordy guides.
- **Method requested.** Set up comprehensive, complete use cases that mimic real work, have an agent run them
  and note every interaction and every button that must be pressed, build a matrix from that, and use it to cut
  steps, clarify, change UI, add features and connect the pieces.

## Root causes confirmed the same day

| Symptom | What the code or receipt shows | Where |
| --- | --- | --- |
| *Review text in Create* never unlocks | `StudioUX.promptTransfer` returns `null` whenever the compile state is `blocked`, and the bridge disables the button with no reason text. | Locked buttons say nothing | *Export compilation* and the bridge button are plain `disabled`; diagnostics render as raw codes (`REFERENCE_COUNT: Profile requires 0..0 references; none were silently discarded`) in a separate panel. | `app/static/prompt-lab.js` compile handler |
| Prompt Lab does not lead to a recipe | The nine compiler profiles are not mapped to the 66 catalog recipes; the handoff is text-only by design and Create still asks the user to choose a matching recipe. | `research/prompt-studio/profiles.json`; `app/static/studio-workbench.js` `initializeDrafts`; tracked as #38 |

## Action map

| # | Slice | What changes | Owner / PR |
| --- | --- | --- | --- |
| 1 | Prompt Lab clarity | Every disabled control shows why and what to do; diagnostics in plain language with a one-click fix where safe (switch to a profile that accepts references); live recompile on input; buttons renamed and grouped; the trace rendered as sentences; the Create handoff names the recipes that match the profile. | worker PR, `Refs #278` |
| 2 | Guided paths | Short, actionable step copy; evidence checked automatically on mount and after edits; the target control highlighted on arrival; a visible step list; one disclaimer footer instead of one per step; a "select this recipe" action where the step is about choosing one. | worker PR |
| 3 | Runs & review + planner | Fix the duplicated labels and notes; a three-line "what this is for / how you get here"; humanised plan names; a state legend; summary at the top of the planner ("3 runs, about N min"); keep/needs-work directly on candidate cards. | worker PR |
| 4 | Asset library review | *Review next* queue with keyboard shortcuts and auto-advance; bulk review on a selection; group by recipe/day/run; "why" chips (hands, face, style, composition) that become tags; no refetch per action. | worker PR |

What this audit does **not** decide: whether the Prompt Lab should pick models and LoRAs automatically (#38
and #232 hold the design), a new task family for sheet/figure/sprite work (#252), and any change to the
"no automatic generation" rule, which stays.

## How the owner's method becomes a fixture

The requested "use cases run by an agent" is slice 6. Each use case is a scripted journey with a stated goal
(for example "edit a character with one reference and keep the winner"), and the harness records per step:
the view, the control, whether it was discoverable without scrolling, any disabled control with no adjacent
reason, and the words of instruction text on screen. The matrix ranks friction by dead ends first, clicks
second. Re-running it after each slice is the measurement; the owner's next first-hand pass is the verdict.
